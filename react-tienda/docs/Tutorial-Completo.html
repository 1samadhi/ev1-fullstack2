Proyecto Fullstack 2

Guía paso a paso: ejecución del servidor, pruebas (Karma/Jasmine), funcionalidades clave, diseño y estructura.

1. Requisitos y Preparación

  • Node.js 18+ y npm instalados (node -v, npm -v).
  • Sistema operativo Windows (el proyecto está configurado y probado en Windows).
  • Ubicación del proyecto: C:\Users\ISMA\Desktop\duoc\2025\2do semestre\FULLSTACK II\1 exp\ev1\react-tienda.
Tip: Si es la primera vez, ejecuta npm install en la carpeta del proyecto.

2. Cómo ejecutar el servidor

  1. Abre una terminal en la carpeta del proyecto.
  2. Ejecuta: npm run dev.
  3. Espera el mensaje del servidor, por ejemplo: 
    [webpack-dev-server] Project is running at:
Loopback: http://localhost:5173/
On Your Network (IPv4): http://192.168.56.1:5173/
  4. Abre http://localhost:5173/ en el navegador.

Rutas principales

  • Inicio: /
  • Productos: /productos
  • Nosotros: /nosotros
  • Contacto: /contacto
  • Carrito: /carrito
  • Login: /login y Registro: /registro
  • Perfil (requiere sesión): /perfil
  • Admin Productos (ADMIN o SELLER): /admin/productos
  • Admin Usuarios (solo ADMIN): /admin/usuarios
  • Blogs (nuevo): /blogs

3. Cómo ejecutar las pruebas (Karma + Jasmine)

  1. Desde la raíz del proyecto, ejecuta: npm run test.
  2. Se lanzará Karma con Jasmine y Webpack. Verás el conteo de suites y el detalle de cada test.
  3. Al finalizar, debe indicar todos los tests aprobados. Ejemplo: 26 specs, 0 failures.

Ubicación de los tests

Los tests NO están dentro de src/. Están en la carpeta tests/ en la raíz del proyecto.

Ruta exacta (Windows): C:\Users\ISMA\Desktop\duoc\2025\2do semestre\FULLSTACK II\1 exp\ev1\react-tienda\tests

  • tests/usersCrud.spec.jsx: Alta, edición y eliminación de usuarios; validación dominio/RUN.
  • tests/authContext.spec.jsx: Login, logout, registro y updateProfile en AuthContext.
  • tests/emailDomain.spec.jsx: Login permitido vs. rechazado según dominio.
  • tests/runUtils.spec.js: formatRun e isValidRun de src/utils/run.js.
  • tests/initializeData.spec.js: Inicialización de datos por defecto y versión del catálogo.
  • tests/productsCrud.spec.js: Operaciones CRUD sobre productos en localStorage.
  • tests/productsData.spec.js: Validación de catálogo inicial, imágenes y precios.
  • tests/regionsData.spec.js: Regiones y comunas disponibles.
Tip: Karma carga archivos que cumplan tests/**/*.spec.js y tests/**/*.spec.jsx. Crea tus pruebas bajo tests/ con ese patrón.

Ejecutar en navegador visual (no headless)

  1. Abre karma.conf.cjs en la raíz del proyecto.
  2. Cambia browsers: ['ChromeHeadless'] por browsers: ['Chrome'].
  3. Opcional: cambia singleRun: true a false para dejar el runner abierto.
  4. Ejecuta: npm run test. Se abrirá Chrome con las pruebas.

Ejecución paso a paso

  1. Verifica dependencias: npm install.
  2. Ejecuta pruebas: npm run test.
  3. Lee el resumen y, si alguna falla, revisa el archivo indicado por Karma.
Tip: Para depurar, puedes aislar una suite usando fdescribe o un test con fit temporalmente.

Crear un test nuevo

  1. En tests/, crea un archivo con el patrón *.spec.js o *.spec.jsx (ej.: miFeature.spec.js).
  2. Escribe una suite básica:
describe('Mi Feature', () => {
  it('hace algo', () => {
    expect(true).toBeTrue();
  });
});

Ejecuta npm run test y verifica que aparezca tu spec en el reporte.

10. Explicación detallada de tests (línea a línea)

Esta sección comenta línea por línea (o por llamada) los tests clave para que entiendas exactamente qué hace cada instrucción.

10.1 usersCrud.spec.jsx — CRUD de Usuarios con AuthContext

01| import React from 'react';
02| import { createRoot } from 'react-dom/client';
03| import { AuthProvider, useAuth } from '../src/contexts/AuthContext.jsx';
04| import { initializeData } from '../src/utils/initializeData.js';
06| const TestHarness = ({ onReady, onUserChange }) => {
07|   const ctx = useAuth();
08|   React.useEffect(() => { onReady && onReady(ctx); }, []);
09|   React.useEffect(() => { onUserChange && onUserChange(ctx); }, [ctx.user]);
10|   return null;
11| };
13| describe('CRUD de Usuarios (AuthContext + localStorage)', () => {
15|   let container, root;
17|   beforeEach(() => {
18|     localStorage.clear();
19|     initializeData();
20|     container = document.createElement('div');
21|     document.body.appendChild(container);
22|     root = createRoot(container);
23|   });
25|   afterEach(() => {
26|     root.unmount();
27|     document.body.removeChild(container);
28|   });
30|   it('agrega usuario válido con dominio permitido y RUN único', (done) => {
31|     root.render(
32|       
33|          {
35|             const res = ctx.register({
36|               id: 'u-10', run: '12312312-3', name: 'Juan', lastName: 'Pérez',
37|               email: 'juan.perez@duoc.cl', password: 'secreto', birthDate: '2001-02-03',
38|               userType: 'USER', region: 'Metropolitana', commune: 'Santiago', address: 'Calle A 123'
39|             });
40|             expect(res.success).toBeTrue();
41|             const users = JSON.parse(localStorage.getItem('users'));
42|             expect(users.some(u => u.email === 'juan.perez@duoc.cl')).toBeTrue();
43|             done();
44|           }}
45|         />
46|       
47|     );
48|   });
  • L01: Importa React para usar hooks y JSX en el test.
  • L02: Importa createRoot para montar el árbol React en un contenedor de pruebas.
  • L03: Importa AuthProvider y useAuth. El provider inyecta el contexto y el hook nos permite usarlo dentro del harness.
  • L04: Importa initializeData para poblar localStorage con usuarios/productos antes de cada test.
  • L06–L11: Define TestHarness. - L07 usa useAuth() para obtener el contexto real de autenticación. - L08 llama onReady(ctx) una vez montado, para ejecutar acciones (login/register) inmediatamente. - L09 escucha cambios de ctx.user y llama onUserChange(ctx) para continuar flujos asíncronos.
  • L13–L15: Declara el describe y variables container, root para montar React.
  • L17–L23: beforeEach. - L18 limpia localStorage. - L19 inicializa datos de prueba. - L20–L22 crea y monta el contenedor en el DOM, y prepara root con createRoot.
  • L25–L28: afterEach desmonta el árbol y remueve el contenedor.
  • L30–L48: Test "agrega usuario válido...". - L31–L33 monta <AuthProvider> con <TestHarness>. - L35–L39 llama ctx.register({...}) con todos los campos: id, run, name, lastName, email, password, birthDate, userType, region, commune, address. - L40 verifica success. - L41–L42 lee users de localStorage, lo parsea y verifica la persistencia con Array.some. - L43 finaliza con done() para indicar test asíncrono completado.

Otros tests del archivo siguen la misma estructura de montaje y usan estas llamadas clave:

  • Registro + eliminación: ctx.register → lectura con JSON.parse(localStorage.getItem('users')) → filtrado y guardado con localStorage.setItem → verificación con Array.some.
  • Edición de perfil: ctx.login para iniciar sesión → ctx.updateProfile para modificar → verificación de ctx.user y persistencia en localStorage.
  • Dominio no permitido: ctx.register con gmail.com → espera success = false y mensaje que contenga "dominio".

10.2 runUtils.spec.js — Utilidades de RUN

01| import { formatRun, isValidRun } from '../src/utils/run.js';
03| describe('Utilidades de RUN', () => {
04|   it('formatRun formatea 12123123k a 12.123.123-K', () => {
05|     const formatted = formatRun('12123123k');
06|     expect(formatted).toBe('12.123.123-K');
07|   });
09|   it('isValidRun acepta 12.346.043-K (dígito verificador K)', () => {
10|     expect(isValidRun('12.346.043-K')).toBeTrue();
11|   });
12| });
  • L01: Importa las utilidades de RUN desde src/utils/run.js.
  • L03: Declara la suite de utilidades de RUN.
  • L04–L07: Caso de formatRun. - L05 llama formatRun('12123123k'), que normaliza (quita puntos, guión, mayúsculas) y formatea "12.123.123-K". - L06 valida exactitud con toBe.
  • L09–L11: Caso de isValidRun. - Llama isValidRun('12.346.043-K') que calcula el dígito verificador (DV) con el algoritmo módulo 11. - Verifica que sea true cuando el DV esperado es "K".
Consejo: Puedes extender este spec añadiendo isValidRunPattern para cubrir el patrón punteado vs. plano; y casos donde el DV no corresponde.

4. Funcionalidades principales del sitio

Autenticación y Perfil

  • Login y Registro en /login y /registro.
  • Validación de correo por dominio (p.ej. profesor.duoc.cl permitido, gmail.com rechazado en tests).
  • RUN chileno con auto-formateo al onBlur y validación de dígito verificador (formatRun, isValidRun).
  • Perfil editable y persistencia en localStorage.

Administración

  • Rutas protegidas con RequireRole y RequireAuth.
  • Admin Productos: gestión de catálogo.
  • Admin Usuarios: alta/edición/eliminación y validaciones.

Catálogo y Carrito

  • Listado de productos y destacados en Home.
  • Carrito con contador en Header y persistencia por localStorage.

Blogs (nuevo)

  • Página /blogs con dos artículos: "Trae Solo 2.0" y "Reseña hackerai.co".
  • Acceso desde Header y Footer.
  • Enlace externo para visitar https://hackerai.co.

5. Diseño y librerías

  • Estilos con Tailwind (config en tailwind.config.js y src/index.css).
  • Iconos con lucide-react en varias páginas.
  • Estructura de Layout: src/components/layout/Header.jsx y Footer.jsx.

6. Estructura del proyecto

  • src/App.jsx: Definición de rutas con react-router-dom.
  • src/pages: Páginas (Home, Productos, Nosotros, Contacto, Carrito, Perfil, Blogs).
  • src/components: Componentes UI y módulos de autenticación/admin.
  • src/contexts/AuthContext.jsx: Contexto de autenticación y utilidades de sesión.
  • src/utils/run.js: Utilidades RUN (normalización, formateo y validación).
  • tests/: Pruebas con Karma/Jasmine.

7. Datos iniciales y usuarios por defecto

  • Inicialización de datos en src/utils/initializeData.js (usuarios y productos por defecto).
  • Credenciales en Login.jsx y README (ej.: admin@duoc.cl).
  • Persistencia: localStorage para usuarios y productos.

8. Solución de problemas

  • Puerto en uso: cierra la instancia anterior del dev server o cambia el puerto en webpack.config.cjs.
  • Pruebas fallan: revisa el archivo indicado por Karma y ejecuta nuevamente npm run test.
  • RUN inválido: utiliza formato XX.XXX.XXX-DV (ej. 12.345.678-5 o K en mayúscula si corresponde).
